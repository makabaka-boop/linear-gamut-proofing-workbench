# 本地 Display-P3 LUT 色彩校样页

打开 `index.html` 即可使用；页面不依赖网络、不上传文件、不读取 ICC，也不声称模拟真实印刷设备。

## 输入

- 网格：最大 128×128、非预乘 8 位 RGBA JSON。
- LUT：5×5×5 线性 Display-P3 RGB，共 375 个 `[0,1]` 有限数。
- 轴顺序固定为 R 最快、G 次之、B 最慢，平坦索引：`((b * 5 + g) * 5 + r) * 3`。

网格 JSON：

```json
{ "width": 2, "height": 1, "data": [255,0,0,0, 0,255,0,255] }
```

LUT JSON：

```json
{
  "size": 5,
  "colorSpace": "linear-display-p3",
  "axisOrder": "R-fastest, G, B-slowest",
  "data": [0,0,0, 1,0,0]
}
```

`data` 必须有 375 个数；上面只展示格式。

## 固定处理顺序

1. 8 位 sRGB 输入解码到线性 sRGB。
2. 用显式矩阵转换到线性 Display-P3。
3. 逐分量裁入 LUT 域 `[0,1]`。
4. 四面体插值。
5. 用显式矩阵转回线性 sRGB。
6. 在 alpha 合成前标记超出 `[0,1]` 的像素（容差 `1e-6`）。
7. 以非预乘 alpha 与不透明 8 位 sRGB 背景合成。
8. 最终线性 RGB 裁入 `[0,1]`，sRGB 编码并 round 到 8 位。

四面体相等分量采用一致的 R 优先于 G、G 优先于 B 裁决。透明像素仍执行颜色管线；若其转回的线性 sRGB 出界，即使 alpha 为 0 也会标记，但最终像素由背景决定。

## CPU 与 WebGL2

- CPU 路径是导出和像素检查器的权威参考。
- WebGL2 路径使用整数 RGBA8UI 输入/输出纹理、RGBA32UI 3D LUT 纹理和相同的 GLSL 四面体逻辑。
- 页面会报告每通道最大差；要求不超过 1 个 8 位级，并检查出界标记一致性。
- 上下文丢失时会立即清空可见预览并显示“预览不可用”，不能恢复旧图；恢复后按当前网格、LUT、背景和标记参数重建。
- 无 WebGL2 时仍可运行 CPU 路径、检查像素和下载。

## 内置测试

页面中的“运行内置测试”覆盖：

- sRGB 传输函数和矩阵往返；
- LUT 平坦轴顺序、R/G 轴交换；
- 六种四面体次序、四角权重和相等分量裁决；
- 端到端小网格进入六种四面体次序；
- LUT 上/下界裁剪；
- alpha `0`、`255`、`1` 的透明边界；
- P3 红造成的负 sRGB 分量、合成前标记和最终裁断；
- WebGL2/CPU 每通道一级以内差异；
- WebGL2 上下文丢失与恢复。

## 输出

- “下载处理 PNG”：最终 8 位 sRGB、不透明背景合成结果。
- “下载逐阶段 JSON”：CPU 各阶段数组、四面体编号、出界像素坐标、背景、矩阵和处理说明。
