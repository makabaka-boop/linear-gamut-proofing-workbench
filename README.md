# 本地 Display-P3 LUT 色彩校样页

纯静态浏览器页面，无外部依赖、无网络请求，不读取 ICC，也不模拟真实印刷设备。它实现一个固定、可审查的参考流程：

1. 输入 1–128 × 1–128 的八位非预乘 RGBA 网格。
2. sRGB 传递函数解码。
3. 从线性 sRGB 转换到线性 Display-P3（D65）。
4. RGB 逐分量裁入 LUT 范围 `[0,1]`。
5. 在 5×5×5 线性 Display-P3 LUT 中做四面体插值。
6. 转换回线性 sRGB。
7. 对合成前落出 sRGB 色域（任一分量 `<0` 或 `>1`，无容差）的像素做单独标记。
8. 与指定的八位 sRGB 背景按 straight alpha 合成。
9. sRGB 编码，再裁断为八位；输出 PNG 为不透明 RGBA。

## 文件

- `index.html`：页面结构。
- `styles.css`：样式和 GPU 丢失遮罩。
- `proof.js`：CPU 参考路径、共享数学定义、WebGL2 渲染器。
- `app.js`：输入、预览、像素检查、下载和上下文恢复。
- `tests.js`：页面内测试。

## 输入格式

### RGBA 网格

```json
{
  "width": 2,
  "height": 1,
  "data": [255, 0, 0, 128, 0, 255, 0, 255]
}
```

- `data` 从左上角开始按行排列。
- 每像素为 R、G、B、A 字节。
- alpha 是非预乘（straight）值；透明像素的 RGB 仍完整经过 LUT，并且可在合成前被标为越界。

### LUT

```json
{
  "colorSpace": "linear-display-p3",
  "size": [5, 5, 5],
  "axisOrder": ["R", "G", "B"],
  "range": [0, 1],
  "entries": [[0, 0, 0]]
}
```

- 必须有 125 个 RGB 表项，或 375 个扁平分量。
- 每个分量必须是 `[0,1]` 内有限数。
- 固定轴顺序为 **R 最快、G 居中、B 最慢**：索引 `((b*5+g)*5+r)`。

## 四面体裁决

格点小数部分按降序排列。若分量相等，固定使用轴优先级 **R > G > B**。CPU 和 GLSL 都采用同一个三项完整比较序列：

- 比较 R/G
- 比较 R/B
- 比较 G/B

四个顶点为：低位点、加第一轴、再加第二轴、加全部三个轴。对应权重为：

`1-f0, f0-f1, f1-f2, f2`

相等分量会令相关权重退化为零，因此数学结果不依赖任意排序；固定裁决只是为了 CPU 与 GPU 的实现、调试表和测试完全一致。

## 预览和一致性

- GPU 路径使用 WebGL2、`RGBA8UI` 输入纹理和 125 个 `vec3` uniform，避免把输入当作浏览器托管的 sRGB 图片再隐式解码。
- GPU 预览结果通过 `readPixels` 回到 CPU，翻转行顺序后与 CPU 输出逐通道比较。
- 页面显示最大差；要求为每通道不超过一个字节级。
- 下载始终使用 CPU 参考路径生成 PNG。

## 上下文丢失

点击“模拟 GPU 上下文丢失”后，预览区域会立即显示不透明的“GPU 预览不可用”遮罩，不继续显示旧帧。上下文恢复时，程序重新编译着色器、重建纹理/uniform，并用当前网格、LUT 和背景重新渲染。

## 内置测试

点击“运行 CPU / WebGL2 / 上下文恢复测试”。测试覆盖：

- LUT R/G 轴交换以及 B 慢轴。
- 六种四面体排序。
- 相等分量裁决。
- alpha=0 和半透明边界。
- LUT 输出回到线性 sRGB 后的负分量。
- 128×128 网格。
- CPU/GPU 每通道差不超过一级。
- WebGL2 上下文丢失、遮罩提示、恢复后重建当前参数。

## 本地打开

可直接用浏览器打开 `index.html`。若浏览器限制本地文件，也可在本目录运行任意静态服务器，例如：

```bash
python3 -m http.server 8000
```

然后访问 `http://localhost:8000/`。
